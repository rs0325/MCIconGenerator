# Macの再起動・異常終了後の扱い

状態は管理rootの`macos/<descriptorSha256>.json`だけに保存する。短cacheの場所は`/private/tmp/mcicon-<uid>-<hash>`から変えない。

起動時に同bootのownerが生存していれば、その描画の終了を待つよう案内する。PIDとprocess開始時刻が一致しなければ前回ownerは終了済みとして扱う。bootが変わった場合も前回の持ち主として片付ける。

前回ownerが終了済みか再起動後なら、VMが動いていれば停止する。次のprepareまたは回収releaseで既存VMを起動し、generation label指定で残ったcontainerを消してから続ける。再起動で短cacheが消えていれば、旧leaseを解放し、次のprepareで新しいgenerationのVMを同じ短pathに作る。

正常releaseではcontainer削除、VM停止、lease resourcesの解放、状態ownerのクリアの順に進む。coreがreleasedを記録し、close後にjobの記録を消す。

再起動証明・終了証明・履歴・操作journalを作らず、旧版の保守コマンドも提供しない。読めない状態、未登録cache、同bootのcache消失、不明なVM状態などは対象と対処を含むエラーで止める。エラーに表示された専用LIMA_HOMEで`limactl delete v`を実行し、表示されたcacheと状態ファイルを削除して再試行する。利用者の別VM・入力cache・出力PNGは削除対象に含めない。

旧状態形式の自動移行は行わない。更新前のMac cache・状態が残っていて新形式として読めない場合も、表示された専用VM・cache・状態ファイルを削除して再生成する。
